# AI Workspace Local 0.5.0-beta.1

Prima beta della serie 0.5. È una **pre-release**: rispetto alla 0.4.0-rc.2 porta gli agenti, i workflow
e il multi-agente a un livello nuovo, aggiunge la valutazione degli agenti e il fine-tuning locale.
Le build non sono firmate e l'addestramento non è mai stato provato con un trainer reale (vedi "Limiti
noti").

## Come aggiornare dalla 0.4.0-rc.2

Il canale di aggiornamento `auto` segue la versione installata: la rc.2 riceve solo release candidate e
versioni stabili, quindi **non vede questa beta**. Per passare alla 0.5.0-beta.1 imposta il canale su
`beta` in Impostazioni → Canale e aggiornamenti, oppure scarica l'installer da questa pagina. Il
database si aggiorna da solo (nuove tabelle, nessuna migrazione dei dati esistenti).

## Novità rispetto alla 0.4.0-rc.2

- **Agenti più capaci**: gli hook hanno quattro eventi in più (`SessionStart`, `SubagentStart`,
  `SubagentStop`, `PreCompact`); più subagenti lavorano insieme nello stesso turno (default 3,
  `agents.max_parallel_subagents`) e non hanno mai più permessi del padre (sandbox, tool, modalità di
  approvazione); un agente può avere uno schema JSON per la risposta finale (validato, con un tentativo
  di correzione) e un budget per run di token, turni e secondi, anche condiviso con i subagenti.
- **Workflow durevoli**: ogni passo ha `retry`, `timeout_s` e `on_error`; lo stato del run è salvato a
  ogni passo e dopo un riavvio i run interrotti riprendono; le approvazioni possono scadere; passi
  `foreach` e `parallel`, sotto-workflow, segnaposto per l'output JSON dei passi, passo `team`. Tutto
  modificabile dall'editor visuale. Nuovo **rewind** dei file di un run (`aiw rewind`, «Ripristina i
  file» in chat).
- **Valutazione degli agenti**: nuovo crate `aiw-eval` e pagina **Valutazioni** con suite di task e
  grader (anche un modello come giudice), report e confronto A/B; pollice su/giù sulle risposte; export
  delle traiettorie in NDJSON con i segreti mascherati (`aiw traces export`, solo CLI e API).
- **Team multi-agente**: pagina **Team** con strategie supervisore, parallelo e catena; un team si
  sceglie in chat come un agente; handoff tra agenti; stato condiviso; **agenti remoti A2A** in
  Integrazioni, usabili come membri di un team.
- **Apprendimento senza pesi**: dopo un pollice giù l'agente propone una **lezione** (una regola per
  `AGENTS.md` o una skill) che entra in vigore solo se la approvi; **ottimizzazione del prompt**
  guidata da una suite di valutazione, mai applicata senza la tua conferma.
- **Fine-tuning locale**: pagina **Addestramento** con trainer esterni (mlx-lm, TRL/PEFT, Unsloth) da
  installare nell'ambiente Python di AIW, dataset dalle traiettorie, job SFT, DPO e GRPO con reward
  verificabili, adapter LoRA registrati e usabili nei profili di inferenza, **router a bandit** tra i
  profili candidati di un agente (`routing.bandit`).

## File della release

| Piattaforma | File |
|---|---|
| Linux x64 | `.deb`, `.rpm`, `.AppImage` |
| Windows x64 | `.msi` (versione MSI 0.5.0.1) e installer `.exe` (NSIS) |
| macOS (universale Intel + Apple Silicon) | `.dmg` (contiene l'`.app`) |
| Android | APK **arm64** non firmato: `aiw-0.5.0-beta.1-android-arm64-unsigned.apk` |
| iOS | **nessun file installabile**: la CI compila solo per il simulatore |
| Daemon `aiw` (CLI) | `aiw-0.5.0-beta.1-linux-x64`, `-windows-x64.exe`, `-macos-arm64` (Metal), con llama.cpp embedded |
| Daemon `aiw` con Vulkan (opzionale) | `aiw-0.5.0-beta.1-linux-x64-vulkan`, `-windows-x64-vulkan.exe` |

Le build Vulkan sono sperimentali e non bloccanti: possono mancare dalla release. CUDA non è
costruito in CI (compilazione locale con `--features llama-cuda`). `SHA256SUMS.txt` elenca i
checksum di tutti i file.

## Build non firmate e non notarizzate

- **macOS**: l'app non è firmata né notarizzata. Al primo avvio usa tasto destro → **Apri** → Apri,
  oppure rimuovi la quarantena:
  `xattr -dr com.apple.quarantine "/Applications/AI Workspace Local.app"`.
  Per il daemon: `chmod +x aiw-0.5.0-beta.1-macos-arm64 && xattr -d com.apple.quarantine aiw-0.5.0-beta.1-macos-arm64`.
- **Windows**: SmartScreen mostrerà "Windows ha protetto il PC": scegli **Ulteriori informazioni** →
  **Esegui comunque**.
- **Linux**: `chmod +x` su AppImage e daemon; nessuna firma dei pacchetti.
- **Android**: abilita l'installazione da origini sconosciute; l'APK non è firmato per il rilascio.
- Gli aggiornamenti automatici passano la mano all'installer del sistema, che chiede la sua
  conferma finché le release non sono firmate.

## Limiti noti

Elenco completo in [docs/STATUS.md](../STATUS.md). In sintesi, per le novità di questa beta:

- **Addestramento mai provato con un trainer reale**: i test usano un `python` finto; gli argomenti
  `DPOConfig` e `GRPOConfig` di TRL non sono verificati, vLLM non è collegato e un adapter PEFT in un
  profilo richiede la conversione in GGUF (solo MLX è gestito). GRPO dalla UI richiede l'app o
  `aiw serve` in esecuzione. I dispositivi già accoppiati devono ripetere il pairing per mostrare
  l'hardware.
- **A2A**: `SendStreamingMessage` (SSE) non c'è, il client interroga `GetTask`. Un team di soli agenti
  remoti non si apre in chat e un handoff verso un agente remoto è rifiutato.
- **Valutazioni**: una valutazione in corso non si può annullare; le suite con un grader `command` si
  scrivono solo da file o da CLI (eseguono comandi con i tuoi permessi).
- **Lezioni**: una lezione approvata non si ritira dalla UI.
- **Rewind**: non copre le cartelle spostate né i file dei subagenti.
- Dopo un ricaricamento della pagina sparisce la traccia annidata di un subagente.

Restano i limiti della rc.2: helper Swift di Apple Foundation Models, installazione dei runtime con
`pip` e Homebrew e giro completo dell'aggiornamento non provati su hardware reale; build GPU e percorsi
nativi Apple e Android idem. Non costruiti: Windows arm64, Linux arm64, Android x86_64/armv7.
Computer-use assente su Linux e Android.
