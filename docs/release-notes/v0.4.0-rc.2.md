# AI Workspace Local 0.4.0-rc.2

Release candidate della serie 0.4. È una **pre-release**: rispetto alla 0.4.0-beta.1 aggiunge
Apple Foundation Models su macOS, l'installazione automatica dei runtime e gli aggiornamenti dalle
release di GitHub. La `v0.4.0-rc.1` è stata creata ma senza file (le release di questo repository
sono immutabili e la pubblicazione è fallita): usa questa. Le build non sono firmate e i percorsi nativi Apple non sono ancora stati provati
su hardware reale (vedi "Limiti noti").

## Novità rispetto alla 0.4.0-beta.1

- **Apple Foundation Models su macOS** (macOS 26 o successivo, Apple Silicon): il runtime `apple-fm`
  usa il modello di sistema di Apple Intelligence tramite un piccolo helper Swift incluso nell'app.
  Annullare una richiesta ferma subito anche la generazione. Su macOS precedenti il runtime resta
  non disponibile con il messaggio "Richiede macOS 26 o successivo".
- **Installazione automatica dei runtime**: dalla pagina Runtime, o dalla scheda di un modello senza
  runtime pronto, un clic installa MLX LM e MLX VLM (in un ambiente Python isolato di AIW,
  `~/.aiw/pyenv`, con Python 3.12 via Homebrew se manca un Python 3.10+), llama.cpp server e Ollama
  (Homebrew). Avanzamento e output in diretta. Solo gestori di pacchetti, mai script scaricati da
  internet: gli altri runtime restano con le istruzioni manuali.
- **Aggiornamenti dalle release di GitHub**, con scelta del canale: `auto` (segue la versione
  installata), produzione (`stable`), `beta`, `alpha`. Controllo all'avvio e ogni 6 ore, download con
  verifica SHA-256 contro `SHA256SUMS.txt`, installazione con l'installer del sistema. Pannello in
  Impostazioni, indicatore nella barra laterale. Le impostazioni `update.*` non possono essere
  cambiate dal livello workspace.
- La release macOS è costruita con Xcode 26 e fallisce se il helper Swift non si compila.

L'app 0.4.0-beta.1 non ha l'aggiornamento automatico: per passare alla rc.2 scarica l'installer da
questa pagina.

## File della release

| Piattaforma | File |
|---|---|
| Linux x64 | `.deb`, `.rpm`, `.AppImage` |
| Windows x64 | `.msi` (versione MSI 0.4.0.102) e installer `.exe` (NSIS) |
| macOS (universale Intel + Apple Silicon) | `.dmg` (contiene l'`.app`) |
| Android | APK **arm64** non firmato: `aiw-0.4.0-rc.2-android-arm64-unsigned.apk` |
| iOS | **nessun file installabile**: la CI compila solo per il simulatore |
| Daemon `aiw` (CLI) | `aiw-0.4.0-rc.2-linux-x64`, `-windows-x64.exe`, `-macos-arm64` (Metal), con llama.cpp embedded |
| Daemon `aiw` con Vulkan (opzionale) | `aiw-0.4.0-rc.2-linux-x64-vulkan`, `-windows-x64-vulkan.exe` |

Le build Vulkan sono sperimentali e non bloccanti: possono mancare dalla release. CUDA non è
costruito in CI (compilazione locale con `--features llama-cuda`). `SHA256SUMS.txt` elenca i
checksum di tutti i file.

## Build non firmate e non notarizzate

- **macOS**: l'app non è firmata né notarizzata. Al primo avvio usa tasto destro → **Apri** → Apri,
  oppure rimuovi la quarantena:
  `xattr -dr com.apple.quarantine "/Applications/AI Workspace Local.app"`.
  Per il daemon: `chmod +x aiw-0.4.0-rc.2-macos-arm64 && xattr -d com.apple.quarantine aiw-0.4.0-rc.2-macos-arm64`.
- **Windows**: SmartScreen mostrerà "Windows ha protetto il PC": scegli **Ulteriori informazioni** →
  **Esegui comunque**.
- **Linux**: `chmod +x` su AppImage e daemon; nessuna firma dei pacchetti.
- **Android**: abilita l'installazione da origini sconosciute; l'APK non è firmato per il rilascio.
- Gli aggiornamenti automatici passano la mano all'installer del sistema, che chiede la sua
  conferma finché le release non sono firmate.

## Limiti noti

Elenco completo in [docs/STATUS.md §2.9](../STATUS.md). In sintesi, oltre ai limiti della beta:
l'helper Swift di Apple Foundation Models, l'installazione dei runtime con `pip` e Homebrew e il giro
completo dell'aggiornamento (dmg, MSI, AppImage) sono coperti da test con processi e server finti, ma
non sono stati provati su un Mac con macOS 26, né su Windows e Linux con una release reale. Build GPU
e percorsi nativi Apple e Android non provati su hardware reale. Non costruiti: Windows arm64, Linux
arm64, Android x86_64/armv7. Computer-use assente su Linux e Android.
